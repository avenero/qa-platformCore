Como desarrollador de software
Quiero que el sistema de CI/CD ejecute los tests automáticamente en cada push
Para detectar regresiones antes de que lleguen a producción

Si el push es a cualquier rama feature/* entonces se ejecutan solo los unit tests y el tiempo de feedback debe ser menor a 2 minutos.

Cuando el pull request es aprobado y se hace merge a develop entonces se ejecutan los tests de integración y los E2E contra el ambiente de staging.

Si algún test falla entonces el pipeline se detiene y el desarrollador recibe notificación inmediata por email y Slack con el link al log del fallo.

El código debe tener cobertura mínima del 80% en líneas y 70% en branches para que el pipeline continúe.

Cuando se hace merge a main entonces se crea automáticamente un tag de versión con el formato v{año}.{mes}.{build} y se despliega al ambiente de producción con estrategia blue-green.

En caso de fallo en producción debe haber rollback automático al deploy anterior en menos de 5 minutos.

Los tiempos de build no deben exceder los 15 minutos para el pipeline completo incluyendo containerización y push al registry.
